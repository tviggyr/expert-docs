# Expert Similar Products — PHASE 2: Magento Admin

PHASE 2 додає інтерфейс Magento Admin для конфігурації з PHASE 1. Admin-інтерфейс є клієнтом наявних Service Contracts: він не має окремої логіки збереження, об’єднання правил або EAV-валідації.

## Навігація та доступ

Розділ доступний за шляхами:

```text
Catalog → Схожі товари → Глобальні правила
Catalog → Схожі товари → Налаштування категорії
```

Для глобальних правил потрібен ACL `Expert_SimilarProducts::global_rules`, для налаштувань категорії — `Expert_SimilarProducts::category_rules`. Усі зміни виконуються через POST із Magento form key.

## Глобальні правила

Сторінка **Глобальні правила** показує вже підключені характеристики, їх `importance`, `comparator`, `tolerance_percent`, `position` і дії редагування або видалення.

Кнопка **Додати характеристику** відкриває пошуковий вибір придатних атрибутів товару каталогу. Він показує label, `attribute_code`, `frontend_input` і `backend_type`. Вибір для глобальних правил не фільтрується через Attribute Set, але використовує `ProductAttributeMetadataProvider` та `AttributeEligibility`, щоб не пропонувати технічні або непридатні атрибути.

Поля comparator доступні лише відповідно до метаданих характеристики. Поле **Допуск, %** показується для `proximity`; для `exact` і `intersection` воно очищується та не надсилається як значення правила. Серверна валідація залишається остаточним джерелом істини.

Видалення глобального правила викликає `GlobalRuleManagementInterface`, тому зберігає атомарне очищення рядків категорії зі станом `disabled` із PHASE 1.

## Налаштування категорії

Сторінка **Налаштування категорії** починається з вибору категорії, без ручного введення ID. Після вибору відображаються:

- глобальні правила та їх стан у категорії;
- явні правила категорії;
- таблиця лише для читання **Ефективна конфігурація**;
- вибір **Додати характеристику**.

Для успадкованого глобального правила менеджер може вибрати:

- **Успадкувати** — видалити явний рядок категорії і знову використати глобальне правило;
- **Перевизначити** — створити або оновити `override` з власними `importance`, `comparator`, `tolerance_percent` і `position`;
- **Вимкнути** — створити `disabled` для цього глобального правила.

Власна характеристика категорії створюється через вибір як `override`; її не потрібно називати «перевизначенням» у менеджерському інтерфейсі.

Таблиця **Ефективна конфігурація** використовує `EffectiveRuleResolverInterface`. Вона показує саме правила, які отримає `SimilarityEngine`, включно з джерелом `global` або `category`.

Категорію обирають лише під час створення налаштування. У редакторі вона є незмінним контекстом: **Перевизначити** створює правило `override` тільки для поточної категорії та не змінює глобальне правило; **Вимкнути** створює її `disabled`-рядок; **Відновити успадкування** видаляє такий явний рядок. Власне правило категорії також діє лише для поточної категорії.

Значення comparator є domain-значеннями і не локалізуються в persistence або API: `exact`, `proximity`, `intersection`. В Admin вони показуються відповідно як **Точний збіг**, **Близькість**, **Перетин значень**.

## Вибір характеристик категорії

Вибір викликає `AvailableAttributeProviderInterface`. `Attribute Set` використовується тільки для пропозиції релевантних характеристик категорії:

```text
Категорія → товари → Attribute Sets → придатні характеристики
```

Якщо є кілька `Attribute Set`, вибір працює з їх об’єднанням і може показати `attribute_set_ids`. Якщо в категорії немає товарів, вибір показує пояснення, але наявні явні правила залишаються доступними для редагування та видалення.

Вибір не пропонує повторно:

- атрибути, які вже мають явні правила категорії;
- атрибути, для яких уже існує глобальне правило.

Для глобального правила треба використати **Успадкувати**, **Перевизначити** або **Вимкнути**, а не додавати друге правило категорії.

## Важливість і способи порівняння

У persistence та REST API використовуються англійські domain-значення. Magento
Admin показує для них українські labels.

| Magento Admin | Domain value | Значення |
|---|---|---|
| Висока | `high` | weight = 3 |
| Звичайна | `normal` | weight = 2 |
| Низька | `low` | weight = 1 |

Важливість впливає на score, але не відфільтровує товар. `position` потрібен
для стабільного порядку й не робить характеристику важливішою.

| Magento Admin | Domain value | Для чого |
|---|---|---|
| Точний збіг | `exact` | точне порівняння |
| Близькість | `proximity` | числова близькість |
| Перетин значень | `intersection` | лише для `multiselect` |

Докладний опис `exact`, `proximity`, `intersection`, допуску та формули score
наведено в [PHASE-3.md](PHASE-3.md#_5).
Той самий `AttributeEligibility` визначає доступні comparator для Admin і REST API.

## REST API

Admin-контролери напряму викликають ті самі Service Contracts, що й REST API з PHASE 1. Admin UI не використовує `/rest/V1` із bearer token. Список REST routes наведено в [PHASE-1.md](PHASE-1.md).

## Що не реалізовано в PHASE 2

PHASE 2 не додає постійний індекс схожості, Magento Indexer, runtime-ранжування за ціною або наявністю, rotation, PDP block, Hyvä-вітрину, cart API, Proxy, Filter Settings чи Accessories.
